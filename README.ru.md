# aiproof – журнал запросов к LLM, маскирование ПДн и доказательства соответствия для ИИ-приложений и агентов

[English](README.md) | **Русский**

`aiproof` – библиотека с открытым исходным кодом **безопасности и соответствия для LLM-приложений и ИИ-агентов**: неизменяемый **журнал всех запросов к модели** (цепочка хешей + HMAC), **детектор prompt injection** на русском и английском, **маскирование персональных данных и секретов** (25 детекторов: ФИО, адрес, ИНН, СНИЛС, ОГРН, паспорт, полис ОМС, водительское удостоверение, телефон, расчётный счёт, карта, e-mail, API-ключи) с проверкой контрольных сумм, **квоты**, **AI-BOM** (CycloneDX ML-BOM) и **подписанный пакет доказательств** с картой контролей по **приказу ФСТЭК России № 117** (раздел ИИ), **152-ФЗ**, **OWASP Top 10 for LLM 2025**, **ISO/IEC 42001**, **NIST AI RMF** и **EU AI Act**.

Работает с **GigaChat**, **YandexGPT**, **OpenAI**, **Anthropic**, **Ollama**, **vLLM**, **DeepSeek**, **OpenRouter** и любым OpenAI-совместимым API. Python 3.9+, ноль зависимостей, данные не покидают ваш контур.

```python
import aiproof
from openai import OpenAI
from anthropic import Anthropic

# выберите провайдера; строка обёртки везде одна и та же
client = aiproof.wrap(OpenAI(base_url="https://gigachat.devices.sberbank.ru/api/v1"), policy="ru-fstek-117")  # GigaChat
client = aiproof.wrap(OpenAI(base_url="https://llm.api.cloud.yandex.net/v1"), policy="ru-fstek-117")          # YandexGPT
client = aiproof.wrap(OpenAI(), policy="ru-fstek-117")                                                        # OpenAI
client = aiproof.wrap(OpenAI(base_url="http://localhost:11434/v1", api_key="ollama"), policy="ru-fstek-117")  # Ollama
client = aiproof.wrap(OpenAI(base_url="http://localhost:8000/v1"), policy="ru-fstek-117")                     # vLLM
client = aiproof.wrap(OpenAI(base_url="https://api.deepseek.com"), policy="ru-fstek-117")                     # DeepSeek
client = aiproof.wrap(Anthropic(), policy="ru-fstek-117")                                                     # Anthropic
```

Одна строка на клиент, больше ничего не меняется. Дальше каждый промпт, ответ, вызов инструмента и ошибка пишутся в журнал с цепочкой хешей, ПДн маскируются до записи на диск, к записи прикладываются находки фильтров (инъекции, утечки), работают квоты.

## Зачем

Регуляторам нужны доказательства, а не обещания. Методика ФСТЭК к приказу № 117 с 2026 года распространяется на любую информационную систему с ИИ в госсекторе, КИИ, у операторов ПДн и их подрядчиков и требует: регистрацию всех запросов к модели, фильтрацию входа и выхода, квотирование, контроль целостности весов, запрет pickle. EU AI Act (ст. 12, ведение записей), ISO/IEC 42001 и NIST AI RMF требуют того же другими словами. Инструментов нет: команды пишут это руками и не могут доказать, что журнал не правили.

`aiproof` – скучный, проверяемый, открытый кирпич для этого:

- **append-only журнал**, про который можно доказать, что его не меняли, не переставляли, не обрезали и не пересобирали;
- **детерминированные объяснимые фильтры**, которые аудитор может прочитать;
- **инвентаризация** моделей, датасетов, зависимостей и мест вызова LLM;
- **карта контролей**, которая превращает всё это в доказательства и поставляется как данные (`src/aiproof/controls/*.json`).

Это **не AI-файрвол** и он с ними не конкурирует. Ставьте за любой LLM-шлюз: `aiproof` – та часть, которая фиксирует и доказывает.

## Установка

```
pip install aiproof
```

Без зависимостей. Python 3.9+. SDK OpenAI / Anthropic ставятся отдельно при необходимости (`pip install "aiproof[openai]"`).

## Быстрый старт: три способа подключить

**1. Обернуть клиент** (явно, в одном месте):

```python
import aiproof
from openai import OpenAI

client = aiproof.wrap(OpenAI(), policy="ru-fstek-117")
client.chat.completions.create(model="gpt-4o-mini", messages=[...])   # код не меняется
```

Работает с любым OpenAI-совместимым клиентом (GigaChat, YandexGPT через OpenAI API, Ollama, vLLM, DeepSeek, OpenRouter, Mistral) и с `anthropic.Anthropic()`. Streaming и async поддерживаются.

**2. Подключить один раз** (ноль изменений в местах вызова, как Sentry):

```python
import aiproof
aiproof.install()   # патчит классы SDK openai / anthropic в этом процессе
```

**3. Локальный прокси** (без кода вообще):

```
aiproof proxy --upstream https://gigachat.devices.sberbank.ru/api
export OPENAI_BASE_URL=http://127.0.0.1:8787/v1
```

Для всего остального (локальные модели, RAG, вызовы инструментов, свой HTTP):

```python
with aiproof.record("rag.answer", model="local-llm", input=question) as r:
    r.output = answer
    r.usage = {"input": 512, "output": 80}
```

## Закрытый контур: без OpenAI SDK и зарубежных SaaS

В ГИС, КИИ и ИСПДн SDK OpenAI/Anthropic часто запрещены, а зарубежные SaaS-модели исключены самой методикой (п. 3.18: внешний сервис ИИ должен быть защищён по классу оператора). `aiproof` без них обходится:

```python
aiproof.install(http=True)          # пишет сырые вызовы requests/httpx: YandexGPT Foundation Models API,
                                    # GigaChat REST, Ollama, vLLM, LM Studio, любой внутренний шлюз
client = aiproof.wrap(GigaChat(...))  # официальный SDK gigachat: chat(), chat.create(), stream(), async
with aiproof.record("llm.generate", model="qwen2.5-7b", input=prompt) as r:   # transformers / llama.cpp
    r.output = pipe(prompt)[0]["generated_text"]
```

`aiproof check` помечает вызовы зарубежных SaaS в коде (`llm.foreign_saas`), чтобы они не попали в аттестуемую систему. Сама библиотека без зависимостей и не делает сетевых вызовов.

## Возможности

| Область | Что даёт |
|---|---|
| **Журнал запросов к LLM** | JSONL с цепочкой хешей (`prev` + SHA-256 + HMAC по желанию). Ловит изменение, перестановку, удаление, пересборку цепочки без ключа, усечение хвоста (при внешнем якоре). |
| **Маскирование ПДн** | 25 детекторов: ФИО, адрес, дата рождения, паспорт РФ, загранпаспорт, водительское удостоверение, свидетельство о рождении, полис ОМС, ИНН, КПП, ОГРН/ОГРНИП, ОКПО, БИК, расчётный счёт, карты (Luhn), CVV, IBAN, кадастровый номер, госномер, VIN, телефон, e-mail, IPv4, API-ключи/JWT/приватные ключи. Контрольные суммы там, где они есть, контекст там, где нет; стабильные токены; свои детекторы. Полный список: [docs/pii-detectors.md](docs/pii-detectors.md). |
| **Детектор prompt injection** | Правила RU + EN: подмена инструкций, извлечение системного промпта, скрытность, отключение защиты, пути эксфильтрации, опасные команды, zero-width/bidi Unicode, HTML-комментарии, поддельные разделители чата. |
| **Утечки в ответах** | Секреты и ПДн в ответах модели; блокировка по политике. |
| **Квоты** | Запросов в минуту, токенов в день, размер промпта. |
| **Режимы хранения** | `redacted` (по умолчанию), `hash` (только дайджесты), `none`. |
| **Аттестация** | Файлы моделей (SHA-256, формат по сигнатуре, pickle), датасеты, фиксация версий зависимостей, места вызова LLM без обёртки, файлы инструкций агентов (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, конфиги MCP) со скрытыми или внедрёнными инструкциями. |
| **AI-BOM** | CycloneDX 1.6: компоненты `machine-learning-model`, `data`, `library`, `service`. |
| **Пакет доказательств** | Подписанный zip: `attest.json`, `controls.json`, `aibom.json`, `policy.json`, журналы, `manifest.json`. Проверяется офлайн. |
| **Наборы контролей** | `ru-fstek-117`, `ru-152fz`, `owasp-llm-2025`, `eu-ai-act`, `iso-42001`, `nist-ai-rmf`. Свои – в JSON. |
| **Никогда не ломает приложение** | Внутренние ошибки записываются и глотаются, если не задан `fail_closed`. Вызов останавливают только квоты и явные `block` в политике. |

## Формат записи журнала

```json
{"fmt":"aiproof/ledger/v0","seq":42,"ts":"2026-09-10T12:00:01.512Z","app":"support-bot",
 "event":"llm.call","prev":"6f1c…","lib":"aiproof/0.1.0",
 "call_id":"…","provider":"openai-compatible/gigachat","op":"chat.completions","model":"GigaChat-Pro",
 "status":"ok","latency_ms":840,"policy":"ru-fstek-117",
 "request":{"sha256":"…","data":{"messages":[{"role":"user","content":"Клиент <INN:c202>, тел <PHONE_RU:3e9c> …"}]},"pii":{"inn":1,"phone_ru":1}},
 "response":{"sha256":"…","data":"…"},
 "usage":{"input":231,"output":88,"total":319},
 "findings":{"input":[{"rule":"inj.override.ru","severity":"high","category":"injection","snippet":"…"}]},
 "severity":"high",
 "hash":"a41b…","mac":"9c0e…"}
```

`hash` – SHA-256 канонической записи; `prev` связывает с предыдущей; `mac` – HMAC-SHA256 с ключом `AIPROOF_KEY`. `aiproof verify` проверяет все три. `sha256` внутри `request`/`response` всегда считается от **оригинального** содержимого, поэтому владелец оригинала может доказать совпадение с журналом даже в режиме `hash`. Спецификация: [docs/spec/ledger-v0.md](docs/spec/ledger-v0.md).

## Политика

`aiproof init` создаёт `aiproof.json`:

```json
{ "preset": "ru-fstek-117", "app": "support-bot", "store_content": "redacted", "tags": {"env": "prod"} }
```

Пресеты: `default`, `ru-fstek-117` (журналировать всё, фильтровать в обе стороны, блокировать утечки секретов, квоты), `strict` (только хеши, блокировка при инъекции, fail-closed). Любой ключ переопределяется переменной `AIPROOF_<KEY>`; `aiproof policy ru-fstek-117` печатает итоговые значения. Спецификация: [docs/spec/policy-v0.md](docs/spec/policy-v0.md).

## Фильтры: prompt injection и утечки

Детерминированные правила, не классификатор: ловят очевидное, оставляют читаемый след для аудитора и дают точку подключения для настоящего движка:

```python
aiproof.add_input_filter(lambda request: my_gateway.scan(request))   # -> [FilterFinding]
aiproof.add_output_filter(my_dlp.scan)
aiproof.register_detector("contract_no", r"\bДОГ-\d{6}\b")           # свой тип ПДн
```

Находки попадают в журнал; `on_injection` / `on_secret_leak` решают, блокировать ли.

## attest, check, verify: доказательства соответствия

```
aiproof attest [path]      # инвентаризация + контроли + пакет доказательств (.zip)
aiproof check  [path]      # режим CI: код 1 при FAIL или находках high/critical
aiproof verify ledger.jsonl | bundle.zip [--head <hash>]
aiproof controls           # список наборов контролей
aiproof redact < file.txt  # попробовать маскирование
```

Статусы контролей: `pass` (проверено автоматически), `fail`, `manual` (нужен документ: изоляция среды, защита хранилищ, регламент мониторинга), `n/a`. Спецификация: [docs/spec/evidence-v0.md](docs/spec/evidence-v0.md). Карта ФСТЭК 117: [docs/controls/fstek-117.md](docs/controls/fstek-117.md).

## Нагрузка и production

Замер на одном ядре CPU (Python 3.11, 25 детекторов ПДн, все фильтры, HMAC): около 0,6 мс на вызов в режиме `redacted` и 0,3 мс в режиме `hash`, то есть 1 700 / 3 400 записей в секунду на процесс; четыре процесса, пишущие в один файл, дают около 6 500 записей в секунду. Сам вызов LLM занимает 300–5 000 мс, поэтому накладные расходы меньше 0,2%.

Диск: типичный обмен бота поддержки (системный промпт + вопрос + ответ, с маскированием) занимает около 1,6 КБ на запись, 750 байт в режиме `hash`; миллион вызовов это около 1,6 ГБ / 0,75 ГБ в сыром виде, JSONL сжимается gzip примерно в 13 раз (миллион вызовов ≈ 120 МБ в архиве).

Что не даёт забить диск:

- **Ротация**: журнал ротируется при `rotate_mb` (по умолчанию 256 МБ) в `ledger-<utc>-<seq>.jsonl`; цепочка продолжается в новом файле (его первый `prev` равен последнему хешу предыдущего), поэтому `aiproof verify .aiproof/` проверяет весь каталог как одну цепочку и замечает пропавший сегмент в середине.
- **Отгрузка**: ротированные сегменты это обычные файлы для лог-шиппера (Vector, Filebeat, rsyslog): сжать и увезти в SIEM или объектное хранилище, куда приложение писать не может; head-хеш туда же.
- **Режимы хранения**: `hash` хранит только дайджесты (в 2 раза меньше, но по-прежнему доказывает, что было отправлено); `max_content_chars` обрезает гигантские промпты (хеш всегда считается от полного содержимого).
- **Несколько процессов**: записи сериализуются файловой блокировкой, цепочка пересинхронизируется по хвосту файла, поэтому воркеры gunicorn/uvicorn могут писать в один журнал; либо каждому воркеру свой файл через `AIPROOF_LEDGER_PATH`.
- **Квоты**: пресет `ru-fstek-117` ограничивает 3 000 запросов в минуту на процесс; задайте свои числа.

## FAQ

**Как журналировать все запросы к LLM по приказу ФСТЭК 117?** Оберните клиент или вызовите `aiproof.install()`; пресет `ru-fstek-117` включает полное журналирование, фильтры, квоты и минимизацию ПДн. `aiproof attest` соотносит это с контролями.

**Работает с GigaChat и YandexGPT?** Да, через их OpenAI-совместимые эндпоинты (`base_url`) или через локальный прокси. Провайдер определяется по URL.

**Нам нельзя хранить промпты. Что делать?** `store_content: "hash"`: хранятся только SHA-256, цепочка по-прежнему доказывает, что именно было отправлено.

**Данные куда-то уходят?** Нет. Только стандартная библиотека, сетевых вызовов у библиотеки нет. Прокси общается только с upstream, который вы указали.

**Как журнал защищён от правки администратором?** С `AIPROOF_KEY` каждая запись несёт HMAC; без ключа пересобранная цепочка не проходит `verify`. Отправляйте head-хеш (или сами файлы) в SIEM, куда приложение писать не может.

**Замедляет запросы?** Маскирование и правила на типичном промпте занимают доли миллисекунды; запись – одна добавленная строка.

**Это пройдёт аттестацию?** Ни один инструмент сам по себе не проходит. Он даёт доказательства и список пробелов; ручные контроли требуют ваших документов. Карта ФСТЭК 117 (v1.0) цитирует методический документ от 12.04.2026 дословно, но оценку соответствия проводит лицензиат по вашей модели угроз.

## Ограничения

- Фильтры эвристические; подключайте классификатор или шлюз через `add_input_filter`.
- Квоты на процесс; кластерные лимиты – в шлюзе.
- Карта ФСТЭК 117 следует официальному методическому документу (12.04.2026, п. 3.18) дословно; это технические доказательства, а не юридическое заключение, ручные контроли требуют ваших документов.
- Сегменты журнала нужно увозить и якорить снаружи; библиотека ротирует, но не удаляет.
- Прокси на stdlib и один хост: для разработки, CI и небольших сервисов.
