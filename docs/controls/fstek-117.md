# Карта контролей `ru-fstek-117`

Источник: методическое обеспечение к приказу ФСТЭК России № 117 в части защиты информации при применении технологий ИИ (12.04.2026). Применяется к ГИС, объектам КИИ, ИСПДн, муниципальным системам и их контрагентам.

Статус карты: **черновик 0.1**. Названия контролей взяты из публичных разборов методики, номера пунктов официального текста в карту пока не внесены. Перед использованием в оценке соответствия сверьте `src/aiproof/controls/fstek_117.json` с текстом документа и внесите номера в поле `ref`. Pull request с точными ссылками приветствуется.

| ID | Фаза | Контроль | Автоматическая проверка |
|---|---|---|---|
| AI-OP-01 | эксплуатация | Регистрация всех запросов к модели и ответов | журнал есть, записи есть, все места вызова LLM обёрнуты |
| AI-OP-02 | эксплуатация | Целостность журналов | цепочка хешей проверена, записи с HMAC |
| AI-OP-03 | эксплуатация | Фильтрация входных данных | `filter_input=true` |
| AI-OP-04 | эксплуатация | Фильтрация выходных данных | `filter_output=true` |
| AI-OP-05 | эксплуатация | Квотирование | хотя бы один лимит в политике |
| AI-OP-06 | эксплуатация | Минимизация ПДн | `redact=true` |
| AI-OP-07 | эксплуатация | Мониторинг и реагирование | журнал есть + документ (регламент, SIEM) |
| AI-DEV-01 | разработка | Целостность моделей, состав (AI-BOM) | sha256 всех файлов моделей |
| AI-DEV-02 | разработка | Запрет pickle | нет pickle-форматов (проверка по сигнатурам) |
| AI-DEV-03 | разработка | Целостность обучающих данных | sha256 датасетов + документ |
| AI-DEV-04 | разработка | Уязвимости фреймворков и зависимостей | манифест зависимостей есть, версии зафиксированы |
| AI-DEV-05 | разработка | Изоляция среды | документ |
| AI-DEV-06 | разработка | Защита хранилищ | документ |
| AI-DEV-07 | разработка | Антивирусная проверка внешних моделей и данных | документ |
| AI-GOV-01 | управление | Учёт ИИ-систем и ответственных | `app` задан, AI-BOM собран |

Что методика не покрывает (и карта тоже): объяснимость, галлюцинации, качество моделей, состязательная устойчивость. Для них нужны внутренние политики организации или отдельные наборы контролей (`--controls`).
